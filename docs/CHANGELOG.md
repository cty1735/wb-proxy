# 更新记录 (Changelog)

本项目以 [workbuddy2api-hub](https://github.com/ardeyouxipianyi/workbuddy2api-hub) v1.7.16 为基座持续叠加改动。README 顶部的「增量功能」只列主要功能，逐条明细在这里。

| 日期 | 功能 |
| --- | --- |
| 2026-10-21 | 鸡蛋视图新增「平台账号」区：**华为云 CodeArts**（浏览器授权登录，自动回调本机入池）与 **Cline**（设备码登录）各是一张卡片。登录一次，凭据由网关保管并自动续期；可加账号、查余额、每日领福利、挑模型（挑选器带 id 搜索、「只看免费」、全选 / 全不选）。平台模型对外 id 带平台前缀（`codearts/GLM-5.2`、`cline/cline-free/minimax-m3.1-flash`），不与自建池或别的提供商撞名，发给上游时自动摘前缀。修掉三处真问题：Cline 的 `Authorization` 少了 `workos:` 前缀会被网关一律 401；CodeArts 没开通每日免费福利时余额 / 领取会甩上游天书，改成先查福利通道并说人话；平台模型与别的池子撞名时会被清单丢掉、请求还发去别家。 |
| 2026-10-21 | 网关模型清单每行新增「测试」与「启用」两件东西。**测试**真发一条请求到网关自己的 `/v1/chat/completions`，和 agent / 客户端走完全同一条链路（模型归属、选号、上游 body、系统提示注入、流式聚合都在里面），结论直接写在行内（可用 + 耗时 + 首字 / 不可用 + 原因，悬停看完整回复或报错）。表头可选口径：**Agent（带工具）**——带一份 `read_file` 工具定义和 agent 式指令，回答或工具调用都算通过，这是默认；**对话（不带工具）**——只要求正常回答。两种口径都不把「HTTP 200 但一个字没有」算成功。**启用开关**写进 `settings.json` 的 `disabled_models`（作用域 = 提供商 + 版本，鸡蛋不分版本）：停用后 `/v1/models` 不再返回该模型，agent 与客户端的选择器里看不到它，直接点名调用也会在分发前被 400 拒绝；面板自己带 `include_disabled=1` 取回灰着的行，随时能再打开。智能体配置写入客户端的模型表同样跳过停用的模型。 |
| 2026-10-21 | 网关模型清单新增**「可用性」列**与**「一键测试模型」**按钮。可用性列把每条模型的实测结论做成一眼能扫的状态徽标：绿点=可用、红点=不可用、琥珀点=测试中（带呼吸动画）、灰点=还没测过；悬停看耗时 / 首字 / 有没有工具调用 / 失败原因 / **测的时间**，与原来的「测试」列同源同数据；表头计数里也带「可用 N · 不可用 N」，一眼看出这个视图整体能不能用。表头「一键测试模型」把当前视图（当前池子筛选后）里每条**启用**的模型挨个真发一次请求，逐条把这一列刷成绿/红。**批量测试改成 4 条并发、单条 30 秒超时**（原来串行 + 120 秒超时，三十来条要好几分钟，看着就是「一直不动」；一条模型 30 秒还没回话，对「能不能用」这问题已经算不可用了）；按钮上实时显示「测试中 9/32 · 1:12」，每秒走一格，正在等的那几条也会把「可用性」刷成琥珀色的「测试中」；测试期间旁边亮出**「停止测试」**，随时能收手（已经测出来的结果照样留着）。并发容易撞上游限流，那种「不是模型的锅」的失败（429 / 503 / no usable account）会单独重试一次再下结论。已停用的模型会被网关直接拒绝，所以跳过并在总结里报数。**测过的结论落到 localStorage：面板刷新、换标签页回来，上一次测出来的绿/红还在，不用每次都重测一遍**（一条模型要真发一次请求，一轮三十来条很花时间）；结论带时间戳，悬停看得出它有多旧，超过 24 小时的自动作废（可用性会变），停用模型时顺手清掉那条。 |
| 2026-10-21 | 网关模型清单的**列头固定**：清单动辄三十多行，滑到下面就分不清哪列是哪列。现在表格外面套一层自己的滚动区（限高 72vh），表头（模型 ID / 名称 / 免费池 / 倍率 / 能力 / 上下文 / 最大输出 / 思考档位 / 采样参数 / 启用 / 可用性 / 测试）吸在滚动区上沿，滚到哪一行都还看得出每列是什么；表头底色不透明，压得住从下面滚上来的行，排序箭头也照旧留在表头里。窄屏（走卡片视图）时表头本来就不显示，那层滚动区一并撤掉，页面里不多一根多余的滚动条。 |
| 2026-10-21 | 出口（国内 / 国际）也按各家自己的走：以前不管走哪家都用全局的「当前出口」，面板停在 WorkBuddy 国内版时，Qoder 的模型会按国内版找账号 —— 而 Qoder 国内版没账号，每个模型都 503 「no usable account for realm 'cn'」。现在走哪家就用那家自己记着的出口（显式 `?realm=` / `X-Realm` / Key 绑定的出口仍然最高优先）。 |
| 2026-10-21 | 四个网关（WorkBuddy / Qoder / Trae / 鸡蛋）之间彻底隔离，模型和请求互不影响：归属按固定顺序判定（WorkBuddy → Qoder → Trae → 鸡蛋），一个 id 只属于一家。以前鸡蛋的供应商池能抢走 WorkBuddy 的同名 id（华为云 CodeArts 池里的 `deepseek-v4.1-flash`），Trae 的别名表按子串匹配又把鸡蛋免费车道的 id 算成自己的。归属判定改为按原样匹配（WorkBuddy 的 id 全小写，Qoder / Trae 的带大写），跨家同名归第一家；显式 `?provider=` / `X-Provider` 仍然最高优先。 |
| 2026-10-21 | 上游在 200 的流里回错误时，客户端看到的是错误而不是「流没有 finish_reason」：平台池拒单回的是 HTTP 200 + `{"error_code": ...}`，网关以前当正文透传、只写一个 `data: [DONE]`，客户端判定流被截断便对死上游反复重试，网关自己还记成成功。现在这类错误会被认出来：错误事件带着上游的真实原因发给客户端，流里补一个 finish_reason 收尾块，非流式直接 502，用量记为失败。 |
| 2026-10-21 | 「全部提供商」把本机没走网关的会话也算进来：这一格 = 经本网关的请求 + 本机各客户端自己记录的会话（本地口径固定排除经网关的部分，两边天然不重复）。KPI、时序、工作回溯、按账号 / 按模型明细与最近请求都按合并后的数据画；账号表把本地客户端列成 `local:` 行（昵称带「本地」），Key 表补一行「本机会话（未走网关）」，性能分位则把本地原始样本接进网关那条分位计算（不是拿两份分位加权），因此首字 / 生成速度仍只由有该样本的网关请求贡献。页首说明条写明本机计入了多少次 / 多少 Token；客户端下拉在「全部」下是本机客户端与网关已配置客户端的并集（本地 `claude` 映射成网关的 `claude-code`）。合并后的 ETag 同时跟网关缓存与本地数据指纹走，本地新增请求不会拿到 304 旧数据。 |
| 2026-10-21 | 数据看板新增「客户端筛选」：按已一键配置本网关的 AI 客户端（DSH / Hermes / OpenCode 等）查看 KPI、曲线、工作回溯、明细与最近请求；「本地」口径下同样按本机会话记录里的客户端（OpenCode / Claude Code / Codex）筛，下拉里列的是本机真正有会话记录的客户端。新请求由一键配置写入的 `X-WB-Agent` 头识别，旧配置按 User-Agent 兜底；历史行没有归属字段，只在「全部客户端」口径里出现。 |
| 2026-10-21 | 看板的「提供商筛选」新增 **本地** 一项：统计本机各客户端（OpenCode / Claude Code / Codex）自己的会话用量，并**排除经本项目网关的请求** —— 那部分网关视图已经记过，两边相加会重复；没走网关的请求网关根本记不下来，这部分直接从客户端的会话记录里读（OpenCode 的会话库、Claude Code / Codex 的会话文件），折成与网关侧同一套载荷结构，KPI、时序、工作回溯、明细与最近请求照常画。页首说明条写明已排除经本网关的请求并列出排除条数；账号池专属区块（剩余用量 / 积分扣减 / 积分获取）在本地口径下收起。 |
| 2026-10-21 | 修复 DeepSeek Harness（DSH）一键配置后报 upstream 400 / code 11128：DSH 系统提示开头的 “You are an AI agent powered by DeepSeek Harness.” 会被 WorkBuddy 的渠道校验拦下。网关转发前只去掉结尾的 “ Harness”，保留 “powered by DeepSeek” 身份；正文里单独出现的 DeepSeek Harness 不受影响。 |
| 2026-10-21 | 首屏不再像卡死：面板解锁后先显示居中的 loading 遮罩，账号、最近请求等首批数据到齐才淡出；首次启动默认鸡蛋时不再先露一屏「0 积分 / 0/0 账号 / 0 个 Key」，模型清单在表内单独显示「加载中」；模型目录与设置页的配额扫描目录改为后台加载（鸡蛋首次汇总要几十秒），超过 8 秒会给「先进入面板（后台继续加载）」的出口。 |
| 2026-10-20 | 新用户开箱即用：冷启动不再为了等慢上游把第一次调用卡住二十几秒（先发内置兜底清单、真目录后台拉）；某一路上游拉挂时另一路照常在（Kilo 的目录实测要 17 秒，原来的 20 秒超时一超就只剩 Zen 那一路，而 Zen 在部分地区被按 IP 拒掉，等于「一个模型都不可用」）；启动横幅直接给出「不登录账号也能用免费模型」的 curl 示例；鸡蛋的所有出口（Zen 免费车道 / Kilo 免费池 / 自建供应商池）可以统一走一个代理槽，代理连不上自动回退直连。 |
| 2026-10-20 | 供应商池的 403 / 429 说人话：403 分三种情况（Key 类型不对 / 模型在出口所在地区不开放 / 模型只开放给 agentic harness 用），429 说明白「每个免费模型每天各 50 次、UTC 0 点重置、充 $10 提到 1000 次/天」，并给出「取消勾选改走内置免费源」的做法。 |
| 2026-10-20 | 池子挑选模型时标出「顶掉内置」：池子选中的 id 若与内置免费源（Kilo / Zen）撞了，这条模型就改走本池、内置那条不再接它（一个 id 只能有一个去处）。卡片上直接写明顶掉了几个，免得把不用 Key 也能用的免费模型弄没了。 |
| 2026-10-20 | 修 Qoder / Trae 流式读取「攒满 64KB 才发」：上游排队（10605 RESOURCE_LIMIT）时 0.2 秒就把错误信封送来，却要等连接断开（实测 3 分钟）才看得见，客户端干等三分钟才报错。改用 read1() 后 0.3 秒就把上游的 403 报出去，正常流式也不再等到攒够 64KB 才吐第一个字。 |
| 2026-10-20 | 自建供应商池新增「测试」：真发一次最小请求，确认这把 Key 能不能推理（拉得到模型目录 ≠ Key 能用 —— OpenRouter 的目录是公开的，垃圾 Key 也拉得到 470 个模型）。池子报错也改口径：说清是哪个池子拒的，并给出「管理/置备 Key 不能用于推理」这类可照着改的提示。 |
